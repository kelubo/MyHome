# MyHome · 家庭应用中心

家里的相关设计，并非是所谓的智能家居项目。涉及网络，智能家居等等方面。
同时，本仓库也是一系列**可独立运行、也可集成在一起**的家庭 Web 应用的“总仓库（hub）”。

## 两种运行模式

### 1. 集成模式（推荐在家用服务器上常驻）
`docker-compose` 启动 nginx，统一入口：

- `/` 或 `/portal/` → 门户仪表盘
- `/apps/home/` → 家庭主页应用
- `/apps/music/` → 音乐播放器（网络电台 + 本地/NAS 音乐库，含后端 API）
- `/apps/wiki/` → 家用手册 Wiki（Markdown 知识库，含后端 API）
- `/apps/album/` → 家庭相册（照片/相册管理，含后端 API，原图与缩略图存于服务器）
- `/apps/calendar/` → 纪念日 / 家庭日历（含后端 API）
- `/apps/carlog/` → 车辆保养记录（含后端 API）
- `/apps/pantry/` → 购物清单 / 冰箱库存（含后端 API）
- `/apps/board/` → 家庭公告板（含后端 API）
- `/apps/docs/` → 家庭文档归档（合同/证件/扫描件，含后端 API，文件存于服务器）
- `/apps/subs/` → 订阅 / 会员续费管理（含后端 API）
- `/apps/tasks/` → 家庭任务看板（含后端 API）
- `/apps/health/` → 健康档案（含后端 API）
- `/apps/recipes/` → 菜谱大全（含后端 API）
- `/apps/menu/` → 每周菜单（含后端 API，联动购物清单）
- `/apps/ledger/` → 家庭账本（含后端 API）
- `/apps/assets/` → 家电 / 资产管理（含后端 API）
- `/apps/books/` → 图书管理（藏书 + 借阅状态，含后端 API）
- `/apps/pets/` → 宠物照护（含后端 API）
- `/apps/vault/` → 家庭密码箱（含后端 API，敏感字段加密存储）
- `/apps/travel/` → 旅游地图（行程游记 + 中国足迹地图，含后端 API）
- `/apps/homeenv/` → 家庭环境记录（按房间记录温湿度/PM2.5/CO₂，含后端 API）
- `/apps/repair/` → 房屋维修记录（台账 + 下次复检提醒，含后端 API）

- `/apps/energy/` → 家庭能耗记录（每月水/电/燃气用量与费用，按年份汇总，含后端 API）
- `/apps/insurance/` → 家庭保险保单（车险/医疗险/房屋险等，到期提醒与年度保费汇总，含后端 API）
- `/apps/certs/` → 家庭证件档案（身份证/护照/房产证等证照，到期临期/过期高亮，含后端 API）
- `/apps/meds/` → 服药提醒打卡（用药计划 + 每日打卡，含后端 API）
- `/apps/contacts/` → 家庭通讯录（家人/服务商/紧急联系人，含后端 API）
- 其它路径按文件/目录直接提供（文档、拓扑图等）

```bash
docker-compose up -d
# 浏览器访问 http://<本机IP>:8080
```

> 所有带后端的应用共用**同一个 PostgreSQL 实例**（`postgres` 服务），每个应用一个独立 database（如音乐播放器用 `music`）做隔离。
> 默认账号 `myhome / ${POSTGRES_PASSWORD}`，**请务必在 `docker-compose.yml` 中改成你自己的强密码**。
> 全部数据统一落在仓库内 `./data/` 目录（bind 挂载），一个目录即可整体备份，详见下文「数据持久化与备份」。

### 多架构支持（ARM / amd64）

家里可能有不同架构的机器（x86_64 台式机/NAS、树莓派/ARM NAS、Apple Silicon Mac 等）。本项目所有镜像**同时支持 ARM (aarch64) 与 amd64**，无需为架构单独维护代码：

- 官方基础镜像（`python:3.12-slim` / `nginx:alpine` / `postgres:16-alpine`）均提供多架构变体；
- Python 依赖使用 `psycopg2-binary` 等预编译轮子，ARM 上**无需源码编译**；
- `music-api` 镜像内 `apt` 安装的 `cifs-utils / nfs-common / mpv / alsa-utils` 在 arm64 与 amd64 源中均有。

**默认用法（推荐）**：在要运行的那台机器上直接构建，镜像会匹配该机架构：

```bash
docker compose up -d --build     # 在 amd64 机器上 → amd64 镜像；在 ARM 机器上 → arm64 镜像
```

**跨平台一次性构建**：若要把同一个镜像 tag 推到仓库、供不同架构机器拉取，用 buildx（见 `scripts/build.sh`）：

```bash
./scripts/build.sh --push myregistry.com/myhome   # 同时构建 linux/amd64 + linux/arm64 并推送
# 推送后，把 docker-compose.yml 里 music-api 的 build: 改为 image: myregistry.com/myhome/myhome-music-api:latest
```

> ⚠️ 不要在 `docker-compose.yml` 里硬编码 `platform:`，否则会强制锁定单一架构、丧失自动适配能力。

### 2. 独立模式（临时查看 / 单应用调试）
每个应用都是自包含的静态站点，可直接打开，或用任意静态服务器：

```bash
# 在仓库根目录
python -m http.server 8080
# 访问 http://localhost:8080/portal/   与   http://localhost:8080/apps/home/
```

> 注意：门户通过 `fetch` 读取 `apps.json`，请用 HTTP 服务访问，不要直接以 `file://` 打开 `portal/index.html`。

### 音乐播放器：本地音乐 / NAS 音乐 / 电台

音乐播放器是**纯前端界面 + 后端 API** 的架构，包含三个音源：

- 📻 **电台**：在线电台（默认国内/中文电台，含央广/CRI 官方 HLS 流与直链 MP3，可自定义）。无后端时仍可凭 `stations.json` + 浏览器本地存储使用；HLS 电台在桌面 Chrome/Edge 经 hls.js 播放，手机/苹果设备原生支持。
- 📁 **本地音乐**：把歌曲放进仓库内 `data/music/`，compose 已挂载到容器 `/music/local`，页面「本地音乐」即可浏览、流式播放（进度条可拖动）。
- 📁 **NAS 音乐**：**在 Web 页面「⚙ 管理 NAS 音乐源」里配置并挂载**（SMB/CIFS 或 NFS），无需改 docker-compose。挂载后作为「音乐库」里的新标签出现；配置存数据库，容器重启会自动重新挂载。

**声音在哪里播放？（播放位置可切换）** 页面底部「播放位置」可二选一：
- 💻 **此设备**：维持原行为——服务器只通过 HTTP 把音频流发给浏览器，**声音在你打开页面的那台客户端出**（Windows / macOS / 手机均可，与服务器 OS 无关）。
- 🔊 **服务器音箱**：声音从**家庭服务器本机**出。服务器需接功放/音箱（全屋共用一路），镜像内用 mpv 解码播放，可切换输出设备、调音量、拖动进度；即使关掉浏览器，服务器仍继续响（适合"全屋一起听"）。

**全局播放互斥（重要）** 后端维护一个互斥状态，规则如下：
- ✅ **多个客户端可同时在各自设备上播放**（多个浏览器标签 / 手机互不限制，每标签一个独立 `client_id`）。
- ❌ **「服务器音箱」与任何客户端播放不能同时出现**（互斥）。
- 冲突时**服务器优先**：若服务器正在全屋播放，客户端发起的播放会被自动静音（本机提示"服务器正在全屋播放，本机已停止"），不会抢走全屋声音；反之，若客户端在播放时有人启动"服务器音箱"，则所有客户端会被自动静音、让位给全屋。
- 客户端每 1.5 秒上报一次播放状态（心跳）；关掉页面/标签超过 12 秒无心跳即视为离线，不再计入互斥。

> 服务器出声模式需要：`docker-compose.yml` 把宿主 `/dev/snd` 透传进 `music-api` 容器（已配置，若宿主机无音频设备请删除该 `devices` 行）；镜像已预装 `mpv`（已在 Dockerfile 安装）。gunicorn 使用单 worker，以保证 mpv 进程与状态一致。

**为 NAS 挂载做准备**（docker 集成模式）：`music-api` 已配置 `cap_add: SYS_ADMIN` + `apparmor:unconfined`，容器内可直接 `mount`；镜像也已安装 `cifs-utils` / `nfs-common`。家庭服务器单机使用此权限可接受。

> NAS 密码等凭据仅保存在本地共享数据库（家庭 LAN 内），未做加密；如需更强隔离可后续改为密钥管理。
> 浏览器无法直接读服务器文件，因此「音乐库」必须有后端（`docker-compose` 集成模式）；「电台」标签页在无后端时仍可凭 `stations.json` + 本地存储使用。

### 家用手册 Wiki

一个**纯文本 Markdown** 知识库，专门收纳家里常用、又怕忘记的信息：WiFi 密码、家电说明书、保修期、物业/水电联系方式等。

- 📝 **页面管理**：新建 / 编辑 / 删除，支持标题、分类、标签与全文搜索（标题、内容、标签、分类均可搜）。
- 🗂 **分类与筛选**：按分类聚合（侧栏显示每类数量），一键筛选。
- 👁 **实时预览**：编辑时右侧实时渲染 Markdown；查看态排版清爽，支持标题、列表、表格、代码块、图片、链接。
- 📎 **附件**：每页可上传 PDF 说明书、图片等（单文件上限 50MB，类型白名单）；图片可一键「插入图片」写入正文，其它文件「插入链接」。附件落盘于仓库 `./data/wiki/`（统一备份），经后端 `/attachments/<id>/file` 托管，不在 nginx 静态根暴露。
- 🔒 **数据全在本地**：页面存于共享 PostgreSQL 的 `wiki` 库；首次启动会自动写入一篇《欢迎使用家用手册》示例页。

> 家用手册为带后端应用，**需以 `docker-compose` 集成模式启动**（含 `wiki-api` 服务与 `wiki` 库）；独立模式下直接打开 `apps/wiki/index.html` 会因连不上后端 API 而提示错误（页面顶部会出现提示条）。

### 家庭相册

一个**照片与相册管理**应用，把家里的照片集中收纳在服务器本地、统一界面浏览：

- 📤 **上传**：点击「⬆ 上传」选择多张图片，或**直接把图片拖拽**到主区域；可选上传到某个相册（默认「未分类」）。单文件上限 100MB，支持 jpg/png/gif/webp/bmp。
- 🖼 **浏览**：响应式缩略图网格，点击任意照片打开**灯箱**大图，支持 ← / → 或左右箭头键切换、Esc 关闭。
- 🗂 **相册**：左侧侧栏新建/删除相册；照片可在灯箱「编辑」里归入相册；可为相册**设置封面**（侧栏显示封面缩略图与张数）。每个相册可填**说明**（短，侧栏/标题下展示）与**备注**（较长自由文本），点相册项的 ✎ 编辑。「全部照片」汇总所有相册。
- ✏️ **编辑与删除**：灯箱里可改标题、描述、**备注**、**拍照时间**、**地点**、**设备/相机**、**人物**、所属相册；删除照片或相册（删除相册会一并删除其中照片）。
- 📷 **照片元数据（EXIF 自动读取）**：上传时自动从照片 EXIF 提取**拍摄时间**、**设备/相机**、**GPS 地点（经纬度）**，无需手动填；地点/设备/人物等均可随后手动覆盖或补充（如把经纬度改成"杭州西湖"、补填同行人物）。所有字段随照片一起存于 `album` 库，灯箱查看态会逐项展示。
- 🔒 **数据全在本地**：原图与缩略图存于仓库 `./data/album/`（统一备份，不在 nginx 静态根暴露），经后端 `/media/` 与 `/thumbs/` 托管；元数据存于共享 PostgreSQL 的 `album` 库。缩略图由 Pillow 在上传时生成（按 EXIF 方向摆正，400×400 内等比缩放），浏览器只加载小图、点开才取原图。

> 家庭相册为带后端应用，**需以 `docker-compose` 集成模式启动**（含 `album-api` 服务、`album` 库与 `./data/album` 卷）；独立模式打开会因连不上后端 API 而在页面顶部提示错误。nginx 已放宽 `client_max_body_size` 至 200m 以允许大照片上传（同样惠及 Wiki 附件上传）。

### 纪念日 / 家庭日历

一个**轻量倒计时**工具，把家里容易忘的日期集中起来：

- 🎂 **类型**：生日、纪念日、缴费、节日、其他；可按分类筛选。
- ⏳ **自动倒计时**：每年 / 每月 / 不重复三种循环；卡片显示"还有 N 天 / 就是今天 / 已过 N 天"。
- 📝 **备注**：每个事件可填备注（如"记得订蛋糕 / 提前订餐厅"）。
- 🔒 **数据全在本地**：存于共享 PostgreSQL 的 `calendar` 库；首次启动写入 3 条示例（爸爸生日、结婚纪念日、物业费缴纳）。

### 车辆保养记录

为家里每辆车建立**保养台账**：

- 🚗 **多车管理**：新建 / 切换车辆（按车牌或名称）。
- 🔧 **记录**：日期、里程、保养项目、费用、下次保养里程 / 日期、备注；按车辆汇总、按日期倒序。
- 🔔 **下次保养提醒**：记录里填"下次里程 / 下次日期"后，列表会以绿色标签提示。
- 🔒 **数据全在本地**：存于共享 PostgreSQL 的 `carlog` 库。

### 购物清单 / 冰箱库存

出门前看一眼，避免漏买或重复买：

- 🛒 **购物清单**：添加要买的东西，勾选"已买"即划线；可设数量、单位、分类。
- 🧊 **冰箱库存**：记录已入库食材的数量与**保质期**，临期（≤7 天）/ 过期自动高亮提醒。
- 🔒 **数据全在本地**：存于共享 PostgreSQL 的 `pantry` 库（纯数据，无需文件存储）。

### 家庭公告板

一块**家庭数字公告墙**：

- 📌 **发布**：标题（可选）+ 内容 + 发布人 + 标签（公告/通知/分工/留言/提醒，按标签着色）。
- 📌 **置顶**：重要通知可一键置顶（置顶项始终排在前面）。
- 🗑 **删除**：随手清理过期内容。
- 🔒 **数据全在本地**：存于共享 PostgreSQL 的 `board` 库；首次启动写入一条置顶欢迎公告。

### 家庭文档归档

把合同、证件、保修卡、说明书扫描件集中归档，避免纸质丢失或散落各处：

- 🗂 **分类**：合同、证件、保修卡、说明书、财务、其他，可按分类筛选；每条文档可记签署/到期/办理日期与说明。

## 部署与运维

> 数据库口令已抽离到仓库根目录的 **`.env`** 文件（已被 `.gitignore` 忽略，绝不进 git），`docker-compose.yml` 中所有口令通过 `${POSTGRES_PASSWORD}` 引用。改密码、备份、恢复等完整运维命令都在本节。

### 环境要求

- 一台 **Linux 主机**（x86_64 或 ARM/aarch64 均可：树莓派、ARM NAS、Apple Silicon 都支持）。
- 已安装 **Docker Engine + Docker Compose v2**（命令是 `docker compose`，不是旧版 `docker-compose`）。
- 端口占用：
  - 宿主 **8080** → 容器 80：门户与反向代理统一入口（所有应用都走这里）。
  - 宿主 **5432** → 容器 5432：**PostgreSQL**，仅供内网/本机使用，切勿对公网开放。
- 磁盘：预留约 2 GB（镜像 + 初始数据）。

### 快速开始

```bash
git clone <你的仓库地址> MyHome
cd MyHome
docker compose up -d --build
```

- 首次构建会编译**各应用后端镜像（含 portal-api）+ portal + nginx**，第一次较慢（几分钟到十几分钟，取决于机器与网络）。
- 构建完成后，`postgres-init` 脚本会自动建库；各 api 首次启动写入示例数据。
- 等待约 10~30 秒让数据库就绪，然后浏览器访问 `http://<主机IP>:8080/`。
- 门户应显示 **31 个应用卡片**，点进去即可使用。

> 所有应用都依赖后端 API（除 `home` 是纯静态）。直接双击打开某个 `index.html` 会因连不上后端而在页面顶部报错——**必须走 `docker compose` 集成模式**。

### 改强密码（务必做）

数据库口令已抽离到仓库根目录的 **`.env`** 文件（已被 `.gitignore` 忽略，**绝不进 git**），`docker-compose.yml` 通过 `${POSTGRES_PASSWORD}` 引用它。默认口令仅用于本地测试，任何真实部署请改为强密码：

- `.env` 内容示例：
  ```ini
  POSTGRES_USER=myhome
  POSTGRES_PASSWORD=你的强密码
  POSTGRES_DB=postgres
  ```
- `docker-compose.yml` 中所有口令均走 `${POSTGRES_PASSWORD}`（**共 31 处**：1 处 `postgres` 服务的 `POSTGRES_PASSWORD` + 30 处各 `*-api` 服务的 `DATABASE_URL`，格式 `postgresql://myhome:${POSTGRES_PASSWORD}@postgres:5432/<app>`），docker compose 自动读取 `.env` 完成替换。
- **改密码只需改 `.env` 一处**：把 `POSTGRES_PASSWORD` 改为你的强密码，再 `docker compose up -d` 让 postgres 与所有 api 用新密码重连。**务必保证 postgres 与各 api 的口令一致**，否则 api 连不上库。
- 改密码属于破坏性变更，建议**先备份**再改（见下文备份）。

### 数据持久化

所有运行时数据集中在仓库 `./data/`（不进 git，需自行备份）：

```
data/
├── postgres/   # 共享 PostgreSQL 实例的全部数据（所有应用的库都在这里）
├── music/      # 本地音乐默认存放处（容器 /music/local）
├── wiki/       # 家用手册附件（容器 /data/wiki）
├── album/      # 家庭相册（原图 photos/ + 缩略图 thumbs/，容器 /data/album）
├── docs/       # 家庭文档归档（容器 /data/docs）
├── vault/      # ⚠️ 家庭密码箱：含加密密钥 vault.key（容器 /data/vault）
└── <app>/      # 其余仅用数据库的应用无文件卷
```

`data/` 与 `backups/` 已被 `.gitignore` 忽略。

### 备份（一键）

```bash
bash scripts/backup.sh
# 产出：
#   backups/db-<时间戳>.sql        数据库逻辑备份（pg_dumpall，最可靠）
#   backups/data-<时间戳>.tar.gz   data/ 下所有应用数据（含 vault.key）
```

- 建议加入 crontab 每日凌晨执行，并保留最近 N 份：
  ```bash
  # 每天 03:10 备份；保留最近 14 天（find 清理）
  10 3 * * *  cd /path/to/MyHome && bash scripts/backup.sh && find backups -name '*.tar.gz' -mtime +14 -delete
  ```
- ⚠️ **vault 的 `data/vault/vault.key` 是解密唯一凭证**，备份一定要包含它；丢失则密码箱数据无法解密。

### 恢复

**A. 整盘恢复（最快，推荐用于整机迁移/回滚）**
```bash
docker compose down
tar -xzf backups/data-<时间戳>.tar.gz -C .
docker compose up -d
```
> 这会整体覆盖 `./data/`（含 postgres 数据目录与各应用数据）。

**B. 仅数据库恢复（用逻辑备份）**
```bash
docker compose up -d postgres
cat backups/db-<时间戳>.sql   | docker compose exec -T -e PGPASSWORD="$POSTGRES_PASSWORD" postgres psql -U myhome -d postgres
```
- 若你**没改过密码**，把上面的 `PGPASSWORD="$POSTGRES_PASSWORD"` 去掉即可（默认口令）。
- B 会按备份重建所有库与表，覆盖现有数据；只恢复单库时先 `DROP DATABASE <app>` 再导入对应片段。

### 外部 / 公网访问（安全）

- 内网访问直接用 `http://<IP>:8080`（确保 8080 在家庭网络可达）。
- **如需从外网访问，务必套一层 HTTPS 反向代理**（Caddy / Nginx Proxy Manager / Traefik 均可），并启用认证（Basic Auth、客户端证书，或前置一个 SSO）。
- 🔒 **强烈建议：家庭密码箱（vault）不要暴露在公网**；即便内网也只在受信任设备访问。vault 页面本身也带安全提示。
- 防火墙：**5432（PostgreSQL）只对内网开放**，不要对公网放行。

### 更新应用

```bash
git pull
docker compose up -d --build     # 重新构建变更过的服务镜像并重启
```
- 数据在 `./data/`，更新不会丢失。
- 即便只改了前端静态文件，`--build` 也最稳妥（portal/nginx 镜像会重新打包静态资源）。

### 故障排查

- **门户打不开 / 应用提示连不上 API**：多半是 postgres 未就绪或某 api 崩溃。看 `docker compose logs postgres` 与 `docker compose logs <app>-api`；确认 `docker compose ps` 中相关服务为 `running`。
- **首次建库失败**：`postgres-init/01-create-dbs.sql` 用条件写法（`SELECT 'CREATE DATABASE ...'` + `\gexec`），可重复执行、库已存在会跳过。改过密码后须保证 `DATABASE_URL` 与 `POSTGRES_PASSWORD` 一致。
- **音乐播放器服务器出声无设备**：compose 给 `music-api` 透传了 `/dev/snd`；无音频设备时会报错，可删除该 `devices` 行（仅用"此设备"播放即可）。
- **上传大文件失败（docs/album）**：nginx 已设 `client_max_body_size 200m`；仍失败检查磁盘空间与文件类型白名单/大小上限（docs 50MB、album 100MB）。
- **vault 页面红色告警**：本机没装 `cryptography` 库，已退化为 base64 混淆（仅调试用）。生产环境镜像内已含该依赖，告警即消失。
- **改密码后旧备份/旧容器不兼容**：改密码是破坏性变更，建议先 `bash scripts/backup.sh` 再改；改完 `docker compose up -d` 让 postgres 与所有 api 用新密码重连。

## 如何新增一个应用
1. 在 `apps/` 下新建文件夹，放入独立可运行的静态站点（至少含 `index.html`）。
2. 在 `apps.json` 的 `apps` 数组追加一项：
   ```json
   {
     "id": "xxx",
     "name": "应用名",
     "description": "简介",
     "icon": "🔧",
     "path": "/apps/xxx/"
   }
   ```
3. 若应用带后端（如 Flask、Go），在 `docker-compose.yml` 增加对应服务，并在 `nginx/default.conf` 增加 `/apps/xxx/` 的反向代理段落。
4. 若应用需要数据库：
   - 在 `postgres-init/01-create-dbs.sql` 追加一行 `CREATE DATABASE <app>;`（用文件内条件写法可重复执行不报错）。
   - 该服务的 `DATABASE_URL` 指向 `postgresql://myhome:${POSTGRES_PASSWORD}@postgres:5432/<app>`（复用同一个共享 PostgreSQL 实例）。
   - 之后 `docker compose up -d --build` 即可；也可直接连库手动 `CREATE DATABASE`。
